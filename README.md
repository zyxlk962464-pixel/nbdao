# NBDAO 自动清仓

一个页面完成钱包连接、读取全部 NBDAO、设定监控时长、基础卖出税率上限和最低到账、有限授权、创建任务、查看进度和取消。无需选择日期或等待 08:00：点击创建时读取最新链时间，默认监控 60 分钟。代币保留在原钱包，每笔从原钱包直接进入既定池，USDT 直接返回原钱包。超过代币单笔限制时，执行服务逐笔分批并重新检查成交条件。

按用户最新要求实现单机必要版本：单页面、单执行服务和 SQLite。没有账户系统、投资组合、复杂策略面板或分布式运行功能。

## 启动

Railway 部署入口已准备：`Dockerfile`、生产启动器、健康检查、持币钱包白名单及完整 SQLite 迁移工具。首次云端只读运行，最终快照导入且本机 Keeper 停止后才开启实盘。步骤见 [Railway 部署与迁移](docs/railway-deployment.md)，包含新服务面板必填设置；`railway.json` 仅用于旧服务兼容。公开配置模板为 `railway.env.example`；私钥与运行数据库不进入 GitHub 或镜像。本次准备不代表已经完成云端上线。

要求 Node.js 24.5 以上、pnpm 和 Foundry。已下载到本项目 `.tools` 的 Foundry 可直接使用；其他机器将 `forge` 和 `anvil` 放在 PATH 中。依赖及合约编译结果由锁文件和源码生成。

```sh
pnpm install
pnpm contracts:build
cp .env.example .env
pnpm dev
```

网页默认为 `http://127.0.0.1:3000`，服务默认监听本机 `8787`。配置不完整时，网页明确显示缺失项并禁用启动交易。

```sh
pnpm typecheck
pnpm test
pnpm test:contracts
pnpm build
```

## 真实链验证

```sh
pnpm check:chain
pnpm test:fork
```

`check:chain` 只查询公开数据并写入 `docs/evidence/chain-check.json`。`test:fork` 在只监听本机的 Anvil 上复制真实链状态，使用公开持有人样本，补充本地 Gas、授权并创建本地测试任务；不向 BSC 发送交易。用户自己的钱包应另外设置 `FORK_HOLDER` 公开地址来验证。它不需要主钱包私钥。

分叉需要支持对应区块历史状态的 RPC。用 `BSC_ARCHIVE_RPC_URL` 指定归档节点；普通公共 RPC 可能快速删除旧状态，出现 `missing trie node` 时不能视为验证通过。读取失败和实际兑换失败均保存至 `docs/evidence/fork-poc.json`。

分叉报告中的“仅协议演进”场景会在本地推进时间并调用已有公开同步方法，保留真实代币代码及业务存储规则。这些受控场景只验证相应执行路径，不能预测未来交易、税率或日期的实收。真实执行器沿用自然卖出顺序，不自动加入额外同步。

## 使用流程

连接钱包后，应用读取 `balanceOf` 和可领取奖励。最低初始全量 USDT 向上换算为每个完整 NBDAO 的最低实收单价，合约逐笔强制执行。不同批次之间不能整体回滚；后续停止时，先前成交仍然有效。

资产卡每 30 秒读取 NBDAO/USDT 池内参考价格，未连接钱包也可查看。连接后显示按钱包快照储备计算的持仓参考估值；余额已包含奖励，不重复叠加 `pending`。参考值未扣卖出税、利润费用、价格冲击和 Gas，不代表实际可到账。读取失败时清除旧价格并显示不可用。

执行监控与页面基础卖出税率均由新区块触发，同一区块去重。HTTP 每 500 毫秒探测一次链头，发现新区块才做业务检查；执行串行处理，繁忙时合并中间通知，完成后读取最新块，不积压过时报价。新任务登记后立即首次检查。RPC 延迟或单次检查耗时可能跳过中间区块，不保证逐块赶上。参考价格与钱包余额保持各自的刷新频率。

未连接钱包也可查看自然同步后的预计基础税率、目标阈值、计算区块与更新时间。页面同时展示基础税的挖矿、团队、资金池与高税部分，以及利润扣费分配、兑换费和 Gas 的不同计算基数；利润扣费展示规则，不冒充本笔的实际税率。字段读取失败时显示不可用，不用旧数值代替有效税率。基础税预计值对应读取区块，交易入块前仍可能变化。

授权总量默认等于当前余额。奖励余量需要用户明确增加；新奖励超过额度时会留下余币并提示，不能自动扩大授权。授权和任务创建由钱包确认；服务运行参数由钱包签名绑定到已创建的任务，执行服务不能私自更改它们。页面不再要求先做免费模拟，填写监控分钟数、最高可接受基础税率和到账底线后，进入有限授权、创建监控任务和参数签名。授权准备冻结余额、到账底线与预算；创建时重新绑定最新链时间作为窗口起点，不把等待授权的时间算入监控。

执行服务在窗口内读取公开状态，按已验证源码计算自然 `sync(true)` 后的基础卖出税率；税率不高于签署阈值时才进行下一笔完整卖出调用与估费，到账或预算不达标则继续等待。发送前再次核对同一模拟区块的税率。默认新任务税率上限为 5%，可设置 0–100 的整数百分比。利润扣费与价格影响由完整卖出模拟和最低实收单价保护覆盖，基础税率不代表总扣费。税率上限属于服务执行规则，现有链上合约强制保护的是额度、时间窗和最低到账，不能保证交易入块时税率仍等于监控值。

候选规划只提供输入量和最低输出提案。发送前会在真实新块上并行核对完整调用返回的实收、税率、Gas、BNB 估价、账户余额与 nonce；签署的区块有效期仍约束这次新验证，超过有效期就停止签名。这样避免仅因前期规划耗时就不断丢弃候选，同时不会把旧报价当作新报价。最后使用已经验证的网络 ID 在本机签名，减少钱包客户端再次访问 RPC 的等待；只读或配置未就绪时不能进入签名发送。

达到税率阈值即尝试成交，不预测整个窗口未来的最低税率。每笔确认后重新检查下一笔；窗口到期立即停止新卖单，未卖出的代币留在钱包，不自动降低阈值、不延长窗口，也不额外发送 `finalizeTask` 消耗 Gas。链上过期任务可由下一次 `createTask` 自动关闭，无需先单独发送结束交易。旧任务的签署参数不受此更新修改；设置新的税率阈值需创建并签署新任务。

浏览器关闭不影响已启动的执行服务。断开钱包不取消链上任务，取消需要钱包提交取消交易。撤销剩余代币授权入口可把 allowance 设置为零。

“全部”是任务窗口、累计额度和已接受尾款阈值内的可卖余额。LP 份额和尚未产生的挖矿收益不在本次范围。卖出本身可能产生待领取奖励，界面分别显示清仓完成、少量余币和停止后仍有余币。任务完成后不自动重启出售未来收益。

网页及执行服务可都在本机运行；生产构建后分别执行 `pnpm keeper` 与 `pnpm --filter @nbdao/web start`。任务执行期间，本机必须持续联网且不休眠。关掉网页不会关掉独立运行的执行服务。本地 Anvil 合约仅用于演练，真实代币任务使用 BSC 主网合约。

实盘需要合约地址、实际执行者、健康 RPC、独立 BNB 估价、依赖基线和明确的预算。缺失时保持只读或暂停状态。监控时长、基础税率上限、最低到账和允许的损耗由用户在界面确认，服务不能在截止前自动降低底线。

价格源应提供有效、未过期的 BNB/USDT 报价。如果使用 BNB/USD，则必须同时配置 USDT/USD，服务先转换计价单位。配置方法见 `.env.example`；预言机缺失、说明不匹配或数据过期会停止净额报价。这里的 Gas 折算和经济净额为估计值，合约强制保护的是实际 USDT 成交单价。
